# max-kit

A control-plane kit for coding agents. It gives any project a small knowledgebase that tells every agent session what to read first, which rules apply, which commands are dangerous and what proves a task is done. You write it once; adapters render it for each agent runtime your team uses.

- **Evidence-based done.** One YAML file per feature with optional acceptance criteria; `max-kit verify` runs its commands and records real output and the commit verified; the check fails when something is `passing` without evidence and warns when files the feature `watch`es changed after the verified commit. A fresh-context `verifier` agent reviews high-risk features against their evidence.
- **Guards.** Session boot context, no push to protected branches, no edits on deploy branches, no hand-written migrations, confirmation for risky commands, an evidence reminder before the agent stops. Written once, bridged into each runtime's hook system.
- **Any stack.** Profiles (`generic`, `rails`, `laravel`, `node`, `django`, `go`) supply migration folders, generators, test commands and risky-command patterns. `max-kit detect` reads each app repo (Gemfile, composer.json, package.json and lockfiles, pyproject.toml, go.mod, compose files) and fills in the profile, test command, migration generator and container.
- **Any runtime.** Claude Code and Codex CLI are built in. Other runtimes are adapters: a folder in this repo, an npm package named `max-kit-adapter-*`, or a local module listed in the config. See [docs/adapters.md](docs/adapters.md).

Plan and roadmap: [docs/plan.md](docs/plan.md).

## Quick start

Requirements: Node.js 20+, git.

```sh
npx github:tinhtran24/max-kit init ~/shop-kb --project shop --id-prefix SHOP
cd ~/shop-kb
git clone <api-repo-url> api && echo /api/ >> .gitignore    # app checkouts live inside
npx max-kit detect --write
npm install
npm run check
npx max-kit install claude        # once per machine: plugin with hooks and the harness skill
```

Open Claude Code in `~/shop-kb` (or in an app repo inside it) and ask it to confirm the boot files it loaded.

To install the Claude Code plugin by hand:

```text
/plugin marketplace add tinhtran24/max-kit
/plugin install max-kit@max-kit
```

The hooks act only inside a folder that has `max-kit.config.json`, so the plugin never interferes with other workspaces.

### Codex CLI

Add `codex` to `targets` (or `init --targets claude,codex`) and run `npm run sync`. It writes `.codex/hooks.json` (hooks call `npx --no-install max-kit`, so run `npm install` first) and `.agents/skills/harness/`; Codex reads `AGENTS.md` itself. Open Codex in the knowledgebase and run `/hooks` to review and trust them: Codex does not run untrusted project hooks.

Codex hooks cannot ask the user, so risky commands are blocked with a reason by default. Set `guards.askFallback` to `"warn"` to let them run with a warning instead.

## Commands

Run inside a knowledgebase (`npm run <script>` wraps each one).

| Command | Does |
| --- | --- |
| `max-kit init [dir] --project <name> --id-prefix <ABC> [--profile <id>] [--targets claude,...] [--detect]` | Create a knowledgebase |
| `max-kit detect [--write]` | Detect each repo's stack, test command, migration generator and container; `--write` fills empty config fields only |
| `max-kit check` | Quality gate: harness lint, index, log, links, boot budget, generated files |
| `max-kit sync [--target a,b] [--dry-run] [--check]` | Render `AGENTS.md`, `CLAUDE.md` and each target's files |
| `max-kit new feature <ID> "<title>" <area> [trigger]` | New draft feature |
| `max-kit verify <ID> [--dry-run] [--allow-risky]` | Run the feature's verification commands in their repos, write the run file (commit, branch, redacted output) and mark it passing on success |
| `max-kit new run <ID[,ID]> <slug> [--repo <id>]` | New evidence file for manual protocols, with the repo's commit |
| `max-kit log <kind> "<title>" [note ...]` | Append to this month's log |
| `max-kit index` / `max-kit rollup` | Regenerate the feature index / log views |
| `max-kit update` | Refresh kit-owned files and re-render after upgrading the kit |
| `max-kit doctor` | Report setup problems |
| `max-kit adapters list` / `adapters show <id>` | Runtimes the kit can render for |
| `max-kit install <runtime>` | Register the kit with a runtime (Claude Code plugin) |
| `max-kit hook <event> --runtime <id>` | Hook entry point called by runtimes |

## Knowledgebase layout

```text
max-kit.config.json       project, repos, branches, profile, targets, guard extensions, budgets
AGENTS.md, CLAUDE.md      generated by sync; never edit by hand
knowledge/
  synthesis/              agent-boot.md, team-rules.md, recent-changes.md (generated)
  harness/                features/<ID>.yml, features-index.md (generated), runs/, verifiers/
  business/  raw/  incidents/  maintenance/  templates/
  log/                    YYYY-MM.md, index.md (generated)
```

App checkouts live inside the knowledgebase folder (listed in `.gitignore` and in `repos`), so one session sees both the rules and the code.

## Configuration

```json
{
  "project": "shop",
  "idPrefix": "SHOP",
  "profile": "generic",
  "repos": [{ "id": "api", "path": "api", "testCommand": "npm test", "migrationGenerator": "npx prisma migrate dev --name <name>" }],
  "targets": ["claude"],
  "adapters": [],
  "branches": { "protected": ["main", "develop"], "deploy": ["staging", "production"] },
  "guards": { "riskyCommands": { "extend": ["\\bsidekiq\\b"] }, "migrationPaths": { "extend": [] }, "disabled": [] },
  "harness": { "staleActiveDays": 30, "staleVerifiedDays": 120 },
  "boot": { "maxChars": 9000, "maxInstructionLines": 80 }
}
```

Full schema: [schemas/config.json](schemas/config.json).

## Developing max-kit

```sh
npm install
npm test                       # unit, guard and golden tests
UPDATE_GOLDEN=1 npm test       # accept intended changes to rendered files
npm run check                  # the kit's own harness (it dogfoods itself)
```

Hooks are guardrails, not a security boundary: an agent can still write and run its own script. The checks that matter also run in `max-kit check`, so put it in CI.

# Feature Harness

The harness answers one question: **what proves this task is done?** It is the contract between user, agent, verifier and reviewer. It is not a backlog.

## Layout

```text
harness/
  features/<ID>.yml           one feature per file
  features-index.md           generated by `npm run index`; read at boot
  runs/YYYY-MM-DD-<slug>.md   evidence, with front matter
  verifiers/                  shared verification protocols reused by several features
```

The feature schema ships with the kit at `node_modules/max-kit/schemas/feature.json`; editors with the YAML language server pick it up from the first line of each feature file.

## Done rule

A feature can be `passing` only when it has a real trigger, a clear behaviour, a verification command or protocol, an expected result, no open unknowns, `last_verified_at`, and at least one evidence path that exists. `npm run check` enforces all of it. Agents may set `draft`, `reviewable`, `active` or `blocked`; they set `passing` only after verification ran.

## States

| State | Meaning | Check requires |
| --- | --- | --- |
| `draft` | Idea, missing clarity | trigger, behavior, verification |
| `reviewable` | Clear enough to assign | same |
| `active` | Being built or verified | warns after `staleActiveDays` without update |
| `blocked` | Cannot progress | `blocker` |
| `passing` | Verified with evidence | evidence, `last_verified_at`, no unknowns; warns after `staleVerifiedDays` |
| `retired` | No longer relevant | hidden from the index |

Thresholds and the id pattern live in `max-kit.config.json` › `harness`.

## Runs

Every run file starts with front matter that the check reads:

```yaml
---
features: [APP-AUTH-001]
date: 2026-01-15
result: passed        # passed | failed | blocked | skipped
tier: high            # high | low, with the reason in the body
repo: api
commit: a1b2c3d       # commit verified; or pr: <url>
---
```

`commit` ties evidence to code, so a `passing` feature whose code moved on can be found and re-verified.

## Commands

```sh
npm run new:feature -- APP-AUTH-001 "Users sign in with email and password" auth
npm run new:run -- APP-AUTH-001 sign-in-smoke [--repo api]
npm run index
npm run check
```
